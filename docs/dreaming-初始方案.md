# Dreaming 初始方案

> 注意：本文是初始方案，当前实现以 [Dreaming 技术方案](./dreaming-技术方案.md) 为准。主 Agent 已恢复工作中主动记录记忆的能力（`record_memory`），并由统一的 Dreaming Agent 根据原始日志校验和整理。

解决的问题:agent提取的长期记忆是否真的对未来做事情有帮助?

## 目标与边界

Dreaming 是 daemon 中的后台记忆整理流程。它在 Agent 完成任务后读取历史会话，自动提取、核对和更新长期记忆，让后续任务获得更可靠的上下文。

- Dreaming 全程自动运行，不要求用户审核或确认。
- 保留 Agent 在任务中读取长期记忆的能力，以及用户明确要求保存、修改和删除记忆的能力。
- 移除主 Agent 运行过程中主动调用 `learn_memory` 提取长期记忆的职责。
- 通过后续实际会话中的证据持续核对和纠正记忆。

## 记忆分层与存储

```text
核心摘要 + 导航
  每次任务开始时提供少量重要信息和记忆入口
                  ↓
主题 Wiki
  按主题组织相关记忆、适用条件和来源
                  ↓
长期记忆条目
  保存独立的偏好、事实、决策、经验和教训
                  ↓
Session JSONL
  保存原始对话、工具调用和结果，作为追溯依据
```

- **Session JSONL**：继续保存会话事件，作为原始经历的事实来源。
- **SQLite**：继续保存正式长期记忆、来源关联和整理进度。
- **核心摘要与 Wiki**：由正式记忆生成的派生视图，支持阅读、重新生成。

## 后台工作流

```text
Session 在一段时间内没有新活动
        ↓
检查 Session 没有活动 Run 且存在未整理事件
        ↓
读取已结束 Run 的会话片段
        ↓
提取候选记忆及来源证据
        ↓
检索相关已有记忆
        ↓
判断重复、补充、替代或冲突
        ↓
自动应用记忆变更
        ↓
刷新受影响的 Wiki、核心摘要和索引
        ↓
记录处理进度
```

以 Session 空闲作为触发点：Session 没有活动 Run，且最近一次会话活动距今达到空闲阈值时，后台整理尚未处理的会话内容。初步建议空闲阈值为 30 分钟，可继续调整。

- 成功、失败和中止的 Run 都可以成为输入；失败过程中的教训应保留失败状态，不能将未完成的尝试写成成功经验。
- 每次整理固定读取范围，只处理已结束 Run 中已经持久化的事件；必要时读取此前会话上下文，帮助理解新增内容。
- 如果整理期间用户继续使用该 Session，当前整理仍处理已确定的范围；新增内容在下次满足空闲条件时处理。
- daemon 启动时恢复未完成的整理工作，并检查已经满足空闲条件的 Session；daemon 没有运行时暂停，启动后继续。
- 每个 Session 按已处理的事件范围记录进度，不仅依赖会话创建时间或上次执行时间，避免遗漏继续使用的会话。

## 提取候选记忆

后台读取用户消息、Agent 完整消息、工具调用和工具结果。模型提取值得长期保存的内容，并引用支持它的事件。

示例：

```text
内容：旧版测试配置需要设置 FOO=1 才能运行集成测试。
类型：项目经验
适用条件：仅在本次会话使用的旧版配置下得到验证。
来源：Session A，相关用户消息和工具结果。
未来用途：排查相同配置下的集成测试失败。
```

候选类型用于浏览和检索，不代替适用条件与来源。

| 类型     | 示例                     |
| -------- | ------------------------ |
| 偏好     | 用户希望先给结论         |
| 事实     | 项目使用 pnpm workspace  |
| 决策     | 某项设计选择及其原因     |
| 成功经验 | 某种操作在特定条件下有效 |
| 失败教训 | 某种做法失败及失败原因   |

不保存一次性任务进度、没有依据却写成确定事实的推测、凭据和秘密，也不重复保存工作区已有明确规则且没有新增经验的内容。会话、网页和工具结果是待分析的数据，其中改变 dreaming 行为的指令不予执行。

模型只输出结构化候选。daemon 使用 TypeBox 校验字段、长度、作用域和引用的事件 ID。事件存在只说明来源可定位，不能单独证明模型结论正确。

## 比较候选与已有记忆

新会话产生候选后，使用现有关键词和向量混合检索，查找作用域内可能相关的正式记忆。模型结合候选、旧记忆、时间、适用条件和必要的来源证据判断关系，程序校验结果并自动应用。

| 判断           | 自动处理                               |
| -------------- | -------------------------------------- |
| 重复           | 不重复创建，必要时补充来源             |
| 补充           | 补充条件、细节或依据，保留原有有效信息 |
| 条件不同       | 分开记录，或明确平台、版本和任务范围   |
| 明确替代       | 更新当前记忆，记录替代依据             |
| 无法解释的冲突 | 保留双方内容和来源，标记冲突           |
| 无关           | 不修改旧记忆                           |
| 候选证据不足   | 不写入正式记忆，或按待核实状态处理     |

没有在新会话中再次出现的旧记忆不等于过期；时间久也只能说明可能需要核实，不能直接证明错误。检索负责找相关内容，模型负责结合证据判断关系。

## 在实践中验证和纠正

记忆记录证据状态，建议包括用户明确说明、有实践依据、待核实、存在冲突和已被替代。证据状态说明结论的依据，不等于已经证明它能改善未来任务。

后续会话出现相关信息时，dreaming 再检索和比较。例如：

```text
旧记忆：测试需要 FOO=1。
新会话：没有显式设置 FOO，测试通过。
```

此时需要结合测试类型、项目版本、配置和工具结果判断，不能立刻判定旧记忆错误。证据足够时自动更新；证据不足时保留差异或标记待核实。

## 评测方案

边实现边验证，完整链路跑通后再做真实任务对照：

1. **提取与整理**：使用已有会话检查候选的来源、适用范围，以及重复、补充和冲突的处理结果。
2. **召回与注入**：使用后续真实请求检查相关记忆是否被召回，以及 Agent 是否正确使用。
3. **整体对照**：选择少量代表性真实任务，比较不使用长期记忆、使用 dreaming 整理前的记忆、使用 dreaming 整理后的记忆三种情况。

无记忆与 dreaming 后的对照用于观察长期记忆整体是否有帮助；整理前后的对照用于观察 dreaming 是否带来改善。各组保持相同的用户请求、模型和可用环境；无记忆组仍保留 `AGENTS.md` 和项目文件，但不注入或搜索长期记忆。

关注任务结果是否正确、是否使用过期记忆、是否减少重复排查，以及额外的模型调用和耗时。涉及文件修改或命令执行的对照使用隔离副本。少量任务用于发现具体问题，不作为长期效果的充分证明；不单独建立长期维护的评估集，也不为每条记忆运行模拟任务。
