# 全局记忆设计

## 范围

全局记忆由用户手动维护的内容和工作区 Dreaming 提出的候选组成，适用于不同工作区。内容既包括用户背景、偏好和工作方式，也包括具备明确适用条件的跨项目经验。项目事实继续保存在所属工作区，不因在多个会话出现就自动成为全局事实。

用户可以在记忆设置中创建、修改和删除全局记忆，也可以在对话中明确要求维护记忆。现有 `user` 作用域承载全局记忆，用户画像只从其中属于个人信息的内容派生，跨项目经验不应被描述为用户画像。

## 候选与整理

每个工作区同时只运行一个整理 Agent，按 Session 和启动时间依次处理该工作区的全部符合条件的 Run。Agent 判断这些材料是否包含有长期复用价值的跨项目内容，没有时不产生候选。候选保留内容、适用条件、依据和可追溯的会话事件引用。工作区整理成功后候选进入全局队列，整理失败时不进入队列。

队列保存在 Dreaming Worker 内存中，由一个全局整理 Agent 串行分批消费。不同工作区可以并发整理，不等待其他工作区；整理运行期间新产生的候选留给后续批次。全局整理复用现有 Dreaming 模型、设置、凭据、取消、超时和上下文压缩机制。

全局整理 Agent 将候选与当前全局记忆比较，判断重复、补充、适用条件不同、替代、冲突和证据不足。它可以拒绝任意候选，也可以保持现有全局记忆不变；没有值得复用的经验时不提交。冲突或修正时更新已有记忆而不是重复创建。未解决的冲突保留条件和来源，不写成无条件结论。草案只在 Agent 正常完成且通过校验后提交；无实际变化时不创建新版本。

## 版本与复用

全局记忆维护发布版本和不可变副本。用户创建、修改或删除全局记忆，以及全局整理产生实际变化时，都发布新版本并保存对应副本。单条记忆同时保留自身 revision、版本内容及来源；用户修改也必须保存修改前后的版本内容和向量副本。

全局整理以读取到的发布版本为基础生成草案，提交时检查版本。用户在整理期间修改记忆时，旧草案不能覆盖用户修改；候选基于新版本重新整理。版本更新与记忆变更在同一事务中提交。

顶层 Run 启动时固定全局与工作区版本，直接加载完整的全局记忆、适用条件和证据状态；运行期间的发布不改变该 Run 的读取结果。工作区记忆继续使用 Wiki 核心摘要和导航。全局记忆是派生上下文，不替代用户当前请求、工作区规则或实际文件。

全局记忆和工作区记忆分别维护适用范围。用户画像只从个人信息派生；全局经验在适用条件满足时复用。关闭记忆使用时不注入或检索任何记忆；关闭学习时不启动新的自动整理。

## 失败与恢复

Worker 退出或重启后，内存中尚未完成的全局候选丢失。模型失败、超时或中止不发布草案，本批候选不再重试。用户修改与整理发生版本冲突时保留候选，使用新的全局版本重新判断。删除来源 Session 时按现有语义移除来源关联，不删除已保存的记忆。
